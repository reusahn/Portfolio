CASE STUDY
01 / GAMEPLAY PREMISE

A clear objective inside an intentionally disorienting world

The design tension is deliberate: the player needs to feel lost enough for the subway to remain uncanny, but not so lost that interaction becomes arbitrary. The project therefore uses a familiar escape-game objective — get out — while making the rules of progression part of what the player has to discover.

GOAL

Escape

The player has an immediately understandable macro objective.

OBSTACLE

Hidden Logic

The environment does not fully explain itself at the beginning.

ACTION

Puzzle + Dialogue

Progress requires both spatial problem solving and conversation.

PAYOFF

Understanding

The route out is tied to learning how the system works.

02 / AI NPC / CONVERSATION

Real-time dialogue as an interactive system

The public project description explicitly identifies a ChatGPT-powered in-game AI and real-time conversation as part of navigation. For technical design, the important point is that the NPC is not framed only as exposition; conversation participates in the player’s attempt to understand and move through the space.

  • Unity was the real-time engine.
  • ChatGPT API was used for the in-game AI conversation.
  • The experience connected conversation to the broader escape / navigation structure rather than presenting it as a separate demo.
Scope note: the existing public project page does not document the internal prompt architecture, exact puzzle code, or an authored behavior tree. This case therefore focuses on the player-facing interaction structure that is verifiable.
03 / NARRATIVE THROUGH SPACE

The subway as both level structure and narrative metaphor

The same environment carries mechanical and narrative functions. Repetition, confinement, transit, and the need to find a way out support the themes of isolation and control while remaining legible as an escape-game space. This is the kind of overlap I am interested in: the world does not stop being playable when it starts carrying story meaning.

04 / ITERATION / OWNERSHIP

Director + Technical Artist means the concept had to survive implementation

The role required carrying the experience beyond an idea into a real-time VR work shown publicly. That background is directly relevant to technical design: prototype the interaction, evaluate whether the player-facing beat is readable, then adjust the system or presentation rather than protecting the first implementation.

TAKEAWAY

A gameplay prototype where spatial exploration, puzzle solving, and AI conversation all serve the same player objective — understanding the system well enough to move through it.
