Project Task

Translate a cinematic cloud language into a playable real-time system

The task was to turn a soft, filmic cloud visual language into an interactive real-time environment. The system needed to look cinematic, remain controllable for shot iteration, and run as a playable scene rather than a pre-rendered effect.

Production Problem

  • Clouds are visually soft and volumetric, but real-time rendering needs hard performance limits.
  • The director needed an image that could be composed cinematically, while the engine needed adjustable parameters, stable playback, and repeatable behavior.
  • A beautiful shader test was not enough; the system had to connect visual controls, animation timing, and virtual camera blocking.

Constraints

  • The visual language needed to preserve concept-art softness and atmosphere.
  • Raymarching / volumetric tests had to stay within runtime performance limits.
  • The system needed artist-adjustable parameters so scenes could be iterated without rewriting the shader each time.
  • Camera composition had to work inside a playable scene, not only as a rendered still.

TD Solution

I decomposed the cloud look into controllable technical parts: density, edge softness, noise scale, movement, transformation timing, depth, and camera readability. I prototyped raymarching / shader approaches, exposed parameters for iteration, connected them to blendshape-driven animation, and blocked shots in Unity so technical systems could support cinematic direction.

Implementation Breakdown

Step 01

Visual Targets

Translated concept art and motion references into technical targets for cloud density, softness, silhouette, motion speed, and camera readability.

Step 02

Shader / Raymarching Prototype

Built Unity shader and raymarching tests to find a real-time approach for soft volumetric forms.

Step 03

Parameter Controls

Exposed adjustable controls for density, noise, softness, timing, and transformation so the look could be tuned without rebuilding the system.

Step 04

Blendshape Animation System

Connected blendshape-driven animation to visual transformation and timing, allowing scene behavior to be directed rather than manually keyed everywhere.

Step 05

Virtual Camera Blocking

Blocked shots, camera distance, movement, and composition inside Unity to make the playable scene read cinematically.

Step 06

Debugging & Playable Delivery

Balanced image quality and runtime stability, iterating shader cost, timing, camera readability, and scene playback.

Debugging / Iteration

Shader costBalanced raymarching quality with runtime performance by reducing unnecessary samples and testing visual thresholds.
Flat cloud volumeAdjusted noise scale, density falloff, and edge softness so forms had readable depth.
Flicker / unstable motionSeparated noise movement and animation timing so cloud motion felt intentional instead of random.
Hard-to-tune lookExposed practical parameters for density, softness, transformation, and timing so the scene could be iterated artistically.
Cinematic readabilityUsed virtual camera blocking to test the effect as a shot rather than judging it only from scene view.
