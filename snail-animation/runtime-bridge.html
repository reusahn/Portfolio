02 / Data flow

Where the animation decisions happen

Runtime pipeline

CharacterMovement velocity, acceleration and falling flag → native UAnimInstance → deterministic state and GroundSpeed → Animation Blueprint State Machine + Blend Space → cached locomotion pose → UpperBody Montage slot → Layered Blend Per Bone → output pose.

Artist-facing pipeline

Animation import and skeleton assignment → editor preflight report → Blend Space samples and retarget chains → in-editor animation debugger → footage and profiler baseline → human QA → documented replacement / handoff.

04 / A focused playable-character acceptance

The 90-point proof to finish in Unreal

01 Animation Blueprint state machine

Create Idle/Walk/Run Blend Space driven by the tested GroundSpeed input; airborne transition; capture PIE and live variable debug values.

02 Layered upper-body montage

Trigger a gesture while locomotion continues, verify slot masks, interrupt handling and ability to replace the montage without code changes.

03 MetaHuman IK retarget

Retarget to a real MetaHuman, inspect root translation and foot contact, document a reproducible before/after correction and chain map.

04 Real Unreal performance evidence

Record Unreal version, hardware, mesh/LOD and animation cost with the Unreal profiler. Report measured results, including failures, instead of estimated frame-rate gains.

05 Handoff reproduction

From a fresh checkout, another person imports the clips and changes one locomotion/gesture asset using the documented steps.

Scope and provenance

This is a new technical prototype, not recovered source from Shininho, Row or When It Seen. Source tests validate decision logic and audit rules only; actual UE5 UAnimInstance build, Editor scripts, skeletal deformation, Blueprint behavior and optimization remain to be verified.
