05 / Independently authored engineering lab

Animation Systems & Production Handoff

A small, reviewable tooling and runtime-systems exercise derived from real animation-integration problems. The source-check utility is separate from the planned Unreal implementation, and both have explicit evidence boundaries.

Existing: Standalone Python manifest preflight + testsPlanned: UE5 Animation Blueprint runtime demo
01 / Code that can be inspected

Animation asset preflight

The independent, standard-library Python validator accepts a CSV manifest of animation clips. It checks missing fields, duplicate asset IDs, frame ranges, FPS bounds, root-motion and facial-track flags, and review status. It can return JSON for a lightweight automated handoff report.

Inputs & contract

asset_id, character, skeleton, fps, start_frame, end_frame, root_motion, face_track, status. Sample rows are explicitly synthetic; they do not represent production assets from Shininho or Row.

Scope & limitations

This is a manifest-level lint. It cannot inspect FBX curves, confirm bone maps, detect visual deformation, load Unreal content, or prove performance. Those require an engine/editor validation pass.

03 / UE5 runtime build specification

The smallest animation-system proof that answers the JD

Build an independent UE5 test level around a mannequin and one MetaHuman. Only once the editor build, video and source are available should the project be presented as an implemented runtime system.

01 Import and validate

Prepare a documented source FBX, skeleton, import settings, naming and animation-sequence inventory. Record any missing curves or incompatible hierarchy as a review failure.

02 Locomotion Blend Space

Build a 1D Speed Blend Space for Idle, Walk, and Run with a defined velocity parameter. State conditions should be inspectable in the AnimGraph and Event Graph.

03 State machine, montage and layers

Build grounded/airborne or idle/locomotion states, explicit transition and reset rules, and a montage for a short upper-body gesture via a layered blend per bone. Record expected behavior during interrupts.

04 IK / Retarget test

Use IK Rig and IK Retargeter on a second compatible character. Check foot sliding, root translation, contact and hand placement rather than assuming that retargeting success means correct motion.

05 QA + performance

Record PIE/Game and Animation Blueprint debug values together. Compare sequence counts, transitions, memory use, and profiler observations in an actual Unreal build. No results are yet recorded.

06 Handoff

Publish animator-facing setup steps, variable definitions, required plugins, failure modes, dependency list and a five-minute demonstration of how another team member changes the animation set.

03 / Clear acceptance criteria

What a production reviewer should be able to reproduce

Acceptance checkEvidence required
State transitionInput speed changes produce idle/walk/run without loop or transition deadlock.
Montage priorityUpper-body montage plays without replacing lower-body locomotion; interruption returns to valid state.
RetargetTarget character animates in the same test with contact and root behavior documented.
Asset validationSample manifest passes; malformed and duplicate entries fail with field-specific messages.
PerformanceReal UE5 build and hardware identified; measured frame and animation costs reported, not invented.
ReusabilityA second animator can replace an animation and reproduce a documented test from a clean checkout.
Current verification status

The source validator is independent Python code. Its seven local unit tests and the three-row synthetic sample manifest passed on November 1, 2026. This is not a test of an Unreal project. The UE5 Animation Blueprint, state machine, Blend Space, montage, IK retarget scene, in-editor benchmark and headset test are specifications, not completed work.
