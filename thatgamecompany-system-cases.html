01 / GAME SYSTEMS · C# + HLSL

Player input as visible behavior.

Independent Real-Time Game · Technical Artist / Technical Director · 2025–2026. The design challenge was to make an expressive, nonstandard visual system react to controllable runtime state instead of behaving like an offline animation.

UNITY URP / REAL-TIME SHADER & INTERACTION FOOTAGE

Directional input → shader motion

A Unity C# controller updates directional parameters within a custom HLSL shader. Input changes the flow of Perlin-style vertex deformation; it does not merely translate a mesh.

Contact logic separate from graphics

Transform, collider, proximity and velocity data coordinate interaction with a raymarched metaball field. Visual rendering and collision remain separate responsibilities.

Repeatable transformations

Four Maya blendshape targets with shared topology were assembled into deterministic runtime states. The director could iterate on timing and appearance without redefining the asset topology.

IMPLEMENTATION MAP
Player direction→Unity C# parameters→HLSL deformation / shader flow→Immediate visual feedback

Separate path: proximity / collision state → gameplay response; the visual field does not replace interaction geometry.

04 / PERSISTENT SURFACE STATE · USER AGENCY

When input changes the world.

Graffiti Freedom · Unity VR. A spray tool converts a gesture into a visible, accumulated material change. This makes the world writable rather than using preauthored one-shot visuals.

PLAYER PAINT INPUT / PARTICLE FEEDBACK / DYNAMIC MASK

Immediate interaction feedback

Player input drives a Unity particle spray, and collisions identify where the spray reaches the virtual geometry.

Writable material state

Collision / surface coordinates update a RenderTexture used as a paint mask. A custom material reads the accumulated mask.

Clear separation of concerns

Input, particle feedback, texture accumulation and final shading can be reasoned about independently when debugging.

INTERACTION MAP
VR spray input→Particle collision→RenderTexture mask→Visible paint on surface

The paint mask retains accumulated marks during the running experience.

05 / CHARACTER · CLOTH · RUNTIME STATE

Character behavior that survives the build.

Mobile Character Runtime · Unity URP / Android. A focused hands-on sample combines character retargeting, animation states, runtime cloth, interactive camera control and physical-device verification.

UNITY REAL-TIME CHARACTER / RUNTIME CLOTH / ANDROID BUILD

Repeatable animation control

Humanoid rig setup and retargeted clips support multiple player-selectable character states rather than a fixed pre-rendered sequence.

Real-time cloth

Skin weights, collision and Unity Cloth constraints were tuned so the garment reacts to different animation states at runtime.

Mobile validation

Camera control, look-at behavior and runtime toggles were tested in an Android APK, making device behavior—not editor playback—the acceptance condition.

Visual scripting that connects content to behavior.
