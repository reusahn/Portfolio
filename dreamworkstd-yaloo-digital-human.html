Project Task

The task was to support Yaloo Studio in building a reusable digital-human pipeline for multiple versions of the same identity: a child version of Yaloo, an elderly version of Yaloo, and a digital reconstruction of Yaloo’s grandmother.

For DreamWorks TD review, this project is shown less as a final artwork and more as a production pipeline case study: how I organized likeness references, prepared character variants, tested facial behavior, debugged real-time presentation issues, and delivered UE5-ready assets for artists and exhibition playback.

Production Problem

The main problem was consistency. Each character variant needed to feel connected to the same identity or family lineage, while also representing a different age, memory, or reconstruction. A small change in facial proportion, skin material, expression response, or eye behavior could make the character feel unrelated or uncanny.

The work also had to survive production conditions: artist feedback, multiple iterations, real-time engine constraints, and exhibition delivery across different venues. The pipeline could not be a one-off sculpting exercise. It needed a repeatable structure that could be reused and explained to collaborators.

Production Constraints

Likeness continuityPreserve recognizable facial relationships across child, elderly, and grandmother versions instead of treating each character as an isolated design.
Artist iterationTranslate subjective artist notes such as “older,” “softer,” “closer to the grandmother,” or “less synthetic” into concrete technical changes.
Real-time deliveryKeep characters usable inside UE5 / MetaHuman workflows for playback, review, and exhibition environments.
RepeatabilityMaintain naming, versioning, reference organization, and handoff logic so later character variants could follow the same process.

TD Solution

I built the work around a reusable character pipeline: reference intake, likeness target definition, variant asset preparation, facial / blendshape testing, material lookdev checks, UE5 integration, debugging, and exhibition handoff.

The TD goal was to make the process understandable and repeatable for artists. Instead of only producing final renders, I prepared each character variant as a production object that could be reviewed, adjusted, tested, and delivered inside a real-time workflow.

Implementation Breakdown

Step 01

Reference Intake & Likeness Map

Collected age references, family resemblance cues, artist notes, and visual targets. I separated stable identity features — eyes, mouth corners, cheek volume, jaw silhouette, brow shape — from age-specific surface changes.

Step 02

Variant Asset Preparation

Prepared each version as a controlled branch of the same pipeline, keeping file naming, asset organization, and iteration history consistent so the child, elderly, and grandmother variants could be compared side by side.

Step 03

Facial Setup & Blendshape QA

Checked facial behavior through expression tests rather than only neutral-pose likeness. I looked for deformation issues around the eyes, mouth, cheeks, and jaw because these areas quickly break likeness during performance.

Step 04

Material / Lookdev Pass

Adjusted skin, surface softness, roughness, and age-specific material response so each variant stayed believable under real-time lighting instead of only looking correct in a static preview.

Step 05

UE5 / MetaHuman Integration

Prepared the characters for UE5 playback and checked scale, materials, facial response, scene placement, and real-time performance. The goal was an artist-reviewable build, not just exported assets.

Step 06

Exhibition Build & Handoff

Packaged real-time-ready characters and supported delivery builds for Songeun Art Award, Gyeonggi MoMA, and West Seoul Museum of Art, including troubleshooting and production handoff.

Debugging / Iteration

ProblemLikeness drift between age variants.
When age features changed too much, the character stopped feeling like the same person or family member.
FixI compared stable facial anchors across versions — eye spacing, cheek structure, jaw / chin relationship, mouth corner shape — and treated age changes as a controlled layer rather than a full redesign.
ProblemNeutral pose looked acceptable, but expressions weakened likeness.
Some facial shapes felt technically correct but emotionally wrong once animated.
FixI tested expression ranges early, checked deformation around eyes and mouth, and used blendshape / facial-response passes as part of the likeness workflow.
ProblemMaterial response changed the perceived age.
Skin roughness, subsurface feel, and lighting could make an elderly version look too artificial or a younger version too flat.
FixI separated geometry / likeness notes from material notes, then tested characters under UE5 lighting conditions before delivery.
ProblemArtists needed to review the character, not debug the file.
FixI prepared reviewable UE5 scenes / builds with organized naming, consistent asset structure, and clear handoff logic so feedback could stay focused on character and performance.
