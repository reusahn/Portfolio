TASK 01 / 04

Procedural Cloud Surface Shader

Problem
An opaque cloud mesh needed player-responsive, wind-like surface motion.
Decision
Use HLSL procedural displacement instead of volumetric raymarching.
Implementation
Unity URP custom HLSL; Perlin noise surface variation + vertex displacement; Fresnel lighting; C# reads WASD/arrow input and sends vector/float parameters that change internal noise-flow direction.
Result
Responsive cloud deformation through a clear C# → HLSL control path.

TASK 02 / 04

Player-Controlled Raymarched Metaball Liquid

Problem
Player-controlled droplets needed to collect into a continuous liquid form without merging the underlying GameObjects.
Decision
Separate simulation/gameplay object logic from rendering.
Implementation
Custom HLSL raymarching/metaballs; similarly sized droplet GameObjects with Colliders; C# transform/velocity input; collision detection; leader/parent droplet; followers constrained by positional correction; metaball fields visually fuse the cluster.
Result
Playable droplet collection that reads as one continuous liquid mass.

TASK 04 / 04

Vertex-Preserving Cloud Growth

Problem
Cloud had to grow small → large, but topology-changing simulation would break blendshape correspondence.
Decision
Use deterministic fixed-topology deformation.
Implementation
Create 4 Maya growth states with identical vertex count/order; connect as blendshape targets; keyframe weights in Unity Timeline/Animation.
Result
Stable, art-directable 4-state growth without topology changes.
