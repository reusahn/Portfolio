Public-Facing Unity Deployment.

Gang Se-hwang is an interactive museum experience delivered through a Unity character runtime. A visitor-facing application connects a custom digital human, UI, camera presentation, animation triggers and physical installation hardware.

01 / PROBLEM & OWNERSHIP

A design problem translated into a runtime system.

The distinction between creative objective and technical contribution is central to this case.

Design / production challenge

An installation must operate for visitors in an uncontrolled, public-facing environment. Real-time character quality mattered, but it also needed reliable camera, animation and UI behavior integrated with presentation hardware.

My technical contribution

I developed and integrated the Unity runtime presentation, character animation triggers, camera and interactive UI behavior, connecting Maya-built digital-human assets and captured motion to a functioning museum installation.

02 / IMPLEMENTATION

How the feature works.

Concrete subsystems and boundaries, not only a list of software tools.

Visitor interaction

C# connects interface events and interactive state to character presentation.

Camera and animation

Unity sequences and camera staging respond to visitor-facing interaction.

Asset-to-runtime pipeline

Custom Maya facial rig and textures integrate with Unity HDRP materials and animation.

Physical deployment

Software must run as part of a complete exhibit with on-site display and camera/hardware constraints.

Visitor input→Unity C# scene state→Character / camera / UI→Museum installation
03 / TECHNICAL DESIGN

Decisions that make iteration possible.

Each technical decision supports clarity, performance, or cross-disciplinary change.

Why separate assets from runtime?

What is deployment evidence?

What does this prove for games?

It demonstrates production delivery and reliable interactive systems, though not commercial multiplayer live-service operations.
