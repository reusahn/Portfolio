Unity implementation

Cloud shading & internal flow

I developed cloud-form shaders and connected their flow and deformation parameters to runtime control. Internal visual motion remains separate from the object’s Transform. The independent C# and HLSL example below isolates that control principle with a simplified shader.

Raymarched metaball droplets

I implemented raymarched metaballs for droplet-like forms that merge continuously. A sampled field defines the visible surface. This droplet renderer is a separate technique from the cloud-form shading, and its visual surface has a different responsibility from gameplay contact logic.

Authored cloud growth targets

I prepared cloud growth states with consistent mesh topology so the intended silhouettes could be edited directly. The archive shows the corresponding Maya states and wireframes. System & design decisions

Cloud form and internal flow

The documented cloud work controls a shader's internal noise flow rather than making object translation stand in for all visual movement. The shape can change while the object's transform remains a distinct control.

Droplet fusion through an implicit field

Raymarched metaballs support the appearance of forms merging continuously. That visual fusion does not automatically produce an equivalent collision shape, so rendering and interaction logic remain distinct responsibilities.

Authored transformation states

Fixed-topology growth targets preserve vertex correspondence. They provide a different kind of control from procedural deformation and let the intended form be edited directly.

Verification and reuse notes

These are newly prepared checks, not reported production incidents.

Design decision
Keep object motion, internal field flow, and authored growth as separate controls. The independent example integrates flow into shader phase and updates per-renderer parameters without moving the object.
Failure case to exercise
Reverse flow while holding the transform fixed. Raise displacement near the camera’s frustum edge. Inspect continuity and clipping. No captured result is reported for this check.
Observable evidence
Record Game view and Inspector together: flow reversal, maximum displacement, unchanged Transform, and renderer bounds. Keep the actual shader and controller revision with the recording.
Reuse boundary
The public example explains phase control and conservative bounds. It does not reproduce the production cloud shader or raymarched metaballs. It does not update colliders, shadow geometry, or displaced normals.

Code example

C# updates per-renderer flow and deformation parameters. The simplified URP shader uses them for vertex displacement.

Independent example, not the original project source. Unity compilation and runtime verification remain pending.

ShaderFlowController.cs

phase += flow * Time.deltaTime;
target.GetPropertyBlock(block);
block.SetVector(Phase, new Vector4(phase.x, 0, phase.y, 0));
block.SetFloat(Amplitude, amplitude * intensity);
block.SetFloat(Frequency, frequency);
target.SetPropertyBlock(block);

HLSL displacement

float3 p=input.positionOS.xyz;
p += input.normalOS * Noise(p*_Frequency + _FlowPhase.xyz) * _Amplitude;
o.positionWS=TransformObjectToWorld(p);
o.positionCS=TransformWorldToHClip(o.positionWS);
o.normalWS=TransformObjectToWorldNormal(input.normalOS);

This stylized example displaces vertices with noise and retains the original normals.

Implementation notes

  • SetFlow validates and clamps the direction. Update integrates it into a phase instead of resetting time or translating the object.
  • MaterialPropertyBlock carries the flow, frequency, and amplitude to this renderer. The controller expands local bounds for the declared displacement range.
  • This sample leaves collision geometry and displaced normals unchanged. Inspect those boundaries before reusing it for a task.

Concept

How can a continuously changing visual form remain controllable enough for both art direction and interaction?

This collaboration required technical decisions to preserve a particular visual character while making it work as a real-time system. Cloud deformation and droplet fusion are different rendering problems. Treating them separately makes their behavior easier to direct and their limitations easier to inspect.

Development

Retrospective planning notes, prepared for this portfolio.

  1. Translate the direction

    Describe the behavior the artist wants to see, then separate shape, movement, and interaction requirements.

  2. Prototype the rendering approach

    Compare explicit mesh deformation with an implicit field according to the visual behavior each can express.

  3. Return to runtime control

    Expose the parameters that matter to direction and inspect the rendered response alongside the game state.
