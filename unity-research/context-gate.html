Research question

Does withholding inapplicable advice make it easier to resume a spatial task?

Compare showing every delayed placement hint with checking whether its move can still be carried out. The possible benefit is fewer misleading interruptions. The possible cost is less available guidance. The prototype is an instrument for studying that tradeoff, not evidence that either policy is better.

Proposed contribution

A Unity harness that revalidates delayed placement hints against explicit object-state preconditions and records what was shown, discarded, or cancelled across paired, reproducible trials.

This is a new extension proposal motivated by the labs’ work on assistance timing and XR tooling. It does not reproduce the IUI study, extend XARP’s code, or claim established research novelty. Read the research context ↗

Controlled comparison

Deliver all

Show a well-formed delayed hint even if its original move is no longer applicable. This is the baseline delivery behavior.

Revalidate

Before display, require the suggested object to remain at its original source slot and its destination to remain empty. Other object changes do not automatically invalidate the hint.

Three objects occupy six slots. A–C have fixed target slots. Paired conditions use the same initial board seed and configured delay. AB/BA order alternates by pair and can be reversed between sessions. This is a small engineering task, not a validated measure of spatial ability.

What would be measured, and why
  • Inapplicable guidance: displayed hints whose source or destination preconditions no longer hold.
  • Assistance availability: displayed, withheld, timed-out, and cancelled requests, reported separately.
  • Task resumption: elapsed time from response processing to the next successful placement. A future human study must define eligibility and handle censoring at trial end.
  • Task outcome: completion, unsuccessful placement attempts, and timeout. More visible help is not assumed to mean better performance.

The first two measures can be checked with engineering replays. Behavioral conclusions require a separate human study with a calibrated task and an appropriate analysis plan.

A small system with explicit boundaries.
  • Pure C# task modelUnique slot occupancy, deterministic hints, and local precondition checks. The model does not depend on a headset or an AI API.
  • Frozen session settingsInspector settings are copied at session start. Paired trial seeds and delivery policy order are saved with the session.
  • Lifecycle and error behaviorReset, pause, trial end, and abort cancel pending hints. Request timeout and malformed-response injection expose failure paths. Logging failures stop the session.
  • Inspectable event trailUTC timestamps, monotonic elapsed time, frame numbers, trial epochs, snapshots, request identifiers, and decision reasons are exported to CSV, JSONL, and JSON.

public bool Applicable(PlacementHint h, out string reason)
        {
            if (!WellFormed(h)) { reason = "malformed"; return false; }
            if (positions[h.token] != h.from) { reason = "source_changed"; return false; }
            if (Occupied(h.to)) { reason = "destination_occupied"; return false; }
            reason = "preconditions_hold";
            return true;
        }

Run & verify
From source to a reviewable run.
  1. Create a Unity 2022.3 LTS desktop project using Built-in or URP. Copy the bundle’s unity/Assets folders into the project’s Assets folder.
  2. Wait for compilation. Run Tools → Jonghoon Research → Create Context Gate Demo. This generates a scene and a settings asset.
  3. Select Settings.asset, inspect the seed and delay, then press Play and Start a new session.
  4. Request guidance and change the relevant object before delivery. Compare the paired policy. Also move an unrelated object to verify that still-applicable advice survives.
  5. Finish or abort. Inspect the output directory shown by the operator interface. Keep the raw JSONL and CSV with the final JSON report.
  6. Run the eight authored Edit Mode tests after installing Unity Test Framework if needed. Build and capture the desktop version before adding XR input.
