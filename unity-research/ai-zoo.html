AI ZOO

2024

Unity / Python · Leap Motion · LLM / voice · Arduino servos · Digital human

A phone-like typed conversation and Leap Motion hand input feed a Unity digital human and a physical sphere driven by three Arduino servos. LLM dialogue, generated voice, lighting, and movement shape one encounter.

Unity implementation

Typed dialogue and digital human

Visitors type into a phone-like keyboard interface. The original archive describes ChatGPT API text generation and ElevenLabs voice synthesis; a Character Creator 4 digital human, refined in Maya, appears in Unity with animation and lip sync. The reply becomes a visible and audible event inside the enclosure. The audience conversation enters through typed text.

Hand sensing and affect encoding

Leap Motion supplies a distinct hand-input path. The project treats text, gestures, and repeated action as signals that can influence an expressive affect state, including fear. That state is an authored control model, not a reading of anyone’s inner experience. Repetition and delay change how the audience can read the response.

Three-servo sphere, voice and light

An expressive state is mapped to the movement of a large transparent sphere through three Arduino-controlled servos and is presented with voice and lighting. Faster, more forceful and offset motion can suggest anger; slower pulses can suggest sadness; fading movement can suggest despair. These are interpretive mappings. Original motor ranges, serial messages, and voice parameter values are not published here.

How the encounter carries affect

AI ZOO artistically extends Shannon’s source–channel–receiver model: expectation precedes a typed turn, and the destination is the viewer’s interpretation. This is a conceptual model of the encounter, not a measured theory of audience psychology.

  1. Nonlinear source

    The plea for help, CCTV-like screen, prewritten messages, and autonomous sphere set expectations before interaction.

  2. Encoding

    Phone-like typed text, Leap Motion gesture intensity, and repeated actions become expressive state values.

  3. Interface channel

    Digital human, generated voice, three-servo sphere, light, and delay make a state perceptible.

  4. Human interpretation

    A viewer might read abrupt motion as anger or pain, and subdued pulsing as fear or loneliness.

  5. Psychological reality

    Pity, guilt, unease, control, and responsibility are possibilities inside the viewer, not system telemetry.

Feedback: typed text or hand action → expressive state → voice, sphere, light and character → audience interpretation → another action.

From dialogue to sphere motion

The visitor types through a phone-like interface. The project archive identifies ChatGPT API for replies and ElevenLabs for voice. The owner describes a multidimensional anger, sadness, fear, and despair representation, accumulated over interaction and translated to motor behavior and vocal expression. A Leap Motion gesture enters through its own input path. Three Arduino servos animate the transparent sphere. Specific wire messages, motor angles and voice settings require the original source and hardware.

For example, stronger anger can yield fast, forceful, offset movement; sadness a slower pulse; despair a fade toward stillness. Fear can shape vocal tension and the viewer’s uncertain reading. These are authored mappings, not evidence that the digital human experiences fear.

Independent C# example

This newly written Unity component accepts structured affect from a separate LLM adapter and calibrated hand intensity from a separate Leap Motion adapter. It emits bounded motion, light and voice intent. A hardware adapter must still enforce servo angle limits and a physical stop.

Portfolio example, not recovered installation code. Unity compilation and Leap Motion, voice, and Arduino runtime checks remain pending. The coefficients are example choices.
public static MotionIntent Map(AffectVector a)
{
    a.Clamp();
    float attenuation = 1f - a.despair;
    return new MotionIntent {
        speed = Mathf.Clamp01((a.anger * 0.75f + a.fear * 0.25f + a.sadness * 0.15f) * attenuation),
        power = Mathf.Clamp01((a.anger * 0.8f + a.sadness * 0.3f + a.fear * 0.1f) * attenuation),
        phaseSpread = Mathf.Clamp01(a.anger * 0.85f)
    };
}

System & design decisions

Keep the input paths distinct

A typed turn and a sensed hand action are different signals. The language-model response and gesture intensity can inform a shared expressive state without turning sensor data into an invented spoken conversation.

Translate affect into bounded outputs

Anger, sadness, fear, and despair are control dimensions in the artistic system. Motion speed, power, phase, lighting, and supported voice controls make state legible; the Arduino layer still needs calibrated limits and safe stopping.

Close the interpretive loop

A person encounters a response, makes an interpretation, and may type or gesture again. That interpretation happens in the visitor; it is not a sensor reading of what the visitor felt.

Concept

When a confined digital human appears afraid, where does the audience’s sense of responsibility come from?

Before a visitor types a word, a CCTV-like display, a looping request for help, and an independently moving transparent sphere set an emotional expectation. The visitor writes through a phone-like keyboard and can use a hand near the Leap Motion sensor. The dialogue and gesture are encoded as control values; voice, character, light, delay, and sphere motion make the response perceptible. A visitor may interpret that output as fear, pain, anger, or loneliness. Those are possible readings of the encounter, not measured audience results or a claim that the AI feels.
