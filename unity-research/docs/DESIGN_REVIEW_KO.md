# A–D 가상 검토 / 제작 결정

아래 대화는 디자인과 연구 관점을 충돌시켜 결과물을 점검하기 위한 시뮬레이션이다. Tobias Höllerer와 Misha Sra의 실제 발언, 평가, 지지나 채용 의사를 뜻하지 않는다. B 역시 실제 사용자의 추가 의사결정을 대신하지 않는다.

A는 웹사이트 디자이너 관점, B는 현재 요청에서 확인된 안종훈의 목표와 표현 선호, C는 Four Eyes의 공개 연구에 근거한 검토 관점, D는 HAX의 공개 연구에 근거한 검토 관점이다.

## 첫 번째 검토 / 무엇을 먼저 보여줄 것인가

A: 첫 화면에서 작품을 알아볼 수 있어야 한다. 거대한 자기소개와 툴 로고를 늘어놓으면 실제 시스템을 찾는 데 시간이 든다. 기존 전시 이미지와 짧은 기여 문장을 사용하자.

B: 작가와 개발자라는 정체성을 함께 보여주되, 내가 무엇을 구현했는지 빨리 보여줘야 한다. 협업 전체를 내 단독 성과처럼 쓰지 말자.

C: 시스템의 어려운 경계를 보여주는 세 사례가 좋다. 제물포는 외부 처리와 디스플레이, Erick Oh는 C#와 렌더링, Escape Metro는 대화와 진행 조건이다.

D: AI라는 단어만으로는 충분하지 않다. 응답이 현재 과제와 어떻게 연결되는지, 조건을 바꿔 무엇을 비교할 수 있는지 드러나야 한다.

반영: 대표작은 세 개로 제한했다. 각 페이지는 기존 실행 영상, 개인 기여, 시스템 경계, 판단, 독립 코드, 증거 상태로 연결된다. 기본 홈페이지는 작품과 구현을 우선한다.

## 두 번째 검토 / 새 프로토타입이 필요한가

D: 오래된 작품에 연구용 logging이나 실험 설계를 나중에 붙였다고 쓰면 안 된다. 지금 실제로 만들 수 있는 연구 도구를 하나 분리하자.

C: 도움을 기다리는 동안 공간의 상태가 바뀌는 상황은 Unity의 상태 제어를 보여주기 좋다. 다만 상태가 바뀌었다는 이유만으로 모든 응답을 버리면 관련 없는 행동도 과하게 차단할 수 있다.

B: 혼자 만들 수 있어야 한다. 거대한 AI 에이전트 플랫폼이나 새로운 모델 학습은 목표에서 멀어진다.

A: 브라우저 시연은 개념 설명으로 쓰고 Unity 실행 화면처럼 꾸미지 말자. 실제 Inspector 이미지가 없으면 가짜 이미지를 만들지 않는다.

반영: Context Gate 하나를 추가했다. 전체 revision 불일치만 보는 대신 특정 물체의 출발 위치와 목적지 점유 상태를 확인한다. 비교 조건과 지연, 과제, provider를 분리했다. C# 소스, scene generator, 상태 관리, 로그, 테스트를 작성했다. 브라우저는 JavaScript 개념 설명으로 명시했다.

## 세 번째 검토 / 100점이라는 말을 무엇으로 바꿀 것인가

C: 실행하지 않은 Unity 소스를 안정적인 연구 시스템이라고 단정할 수 없다. compile, desktop run, log consistency, headset input은 서로 다른 확인 항목이다.

D: 조건 차이를 구현한 것과 사람이 더 잘 수행한다는 결과는 다르다. 연구 질문은 있어도 효과와 신규성은 아직 주장할 수 없다.

B: 증거가 부족하다는 이유로 모든 제작을 미루지 말자. 공개 가능한 페이지, 독립 예제와 촬영 지시서는 지금 완성하자.

A: 검증 문구는 상세페이지와 evidence 페이지에 정리하고 메인 화면을 미완료 체크리스트처럼 만들지 말자. 첫 화면은 실제 작업으로 설득해야 한다.

반영: 메인에서는 세 사례와 연구 방향을 간결하게 소개한다. 상세페이지와 Evidence에서 기존 구현, 이번 소스 구현, 추가 제작, 검증 필요를 명확히 분리했다. 실제 캡처를 요구하는 지점에는 정확한 화면과 동작을 지정했다.

## 교수님별 읽는 순서

- 기본: Erick Oh → 제물포 → Escape Metro → Context Gate.
- Tobias용 XR route: 제물포 → Erick Oh → Escape Metro. 외부 과정과 시각적 시스템을 제어하는 역량부터 읽는다.
- Misha용 Human + AI route: Escape Metro → 제물포 → Erick Oh. 언어가 과제와 연결되는 사례부터 읽고 Context Gate로 확장한다.

사이트는 같은 사실과 같은 증거를 쓴다. 교수별로 서로 다른 경력을 만드는 방식이 아니다.

## 지금 전달 가능한 것과 다음 단계

지금 전달 가능한 것은 실제 영문 사이트, 상세페이지, 독립 C#·HLSL·Python 예제, Unity 실험 소스, 테스트, 제작 지시서다.

현재 환경에서 Unity와 브라우저 렌더링을 실행할 수 없었다. JavaScript 모델 검사와 소스·링크 검사는 이 한계와 분리해서 기록한다. 영상·빌드·사용자 실험을 만들지 않은 상태에서 네 관점 모두의 실제 완성도를 100점이라고 확정하지 않는다.

가장 큰 다음 증거는 페이지 장식을 더하는 것이 아니라 Context Gate의 Unity compile / run과 기존 사례의 실제 Inspector 녹화다.
