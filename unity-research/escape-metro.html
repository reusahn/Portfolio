Problem & individual contribution

Connect generated replies to explicit game rules.

The NPC needed to contribute to a playable escape task. A conversational response had to relate to what the player was trying to discover and what the game could allow next.

I implemented: Unity VR interaction, NPC integration, response presentation, and dialogue-linked progression.

I developed the Unity VR experience and connected GPT-based NPC dialogue to puzzle and progression conditions. Escape Metro and RedFlight AI refer to the same project. The existing record describes character response, voice presentation, and password discovery. Exact API transport and progression code remain subject to source-level confirmation.

Implementation decisions

Why the system is structured this way.

01

Give dialogue a task

The player talks to the NPC to make progress in an escape scenario. The point is the connection between language and a concrete objective.

02

Keep the engine boundary explicit

Unity owns the interactive world and progression. The public source example demonstrates a stricter boundary in which generated replies provide presentation cues while a separate game rule authorizes an unlock.

03

Treat delayed replies as stateful events

Timeouts, duplicate replies, and scene resets matter once a reply is part of gameplay. The new example validates turn and scene identifiers. These safeguards are new illustrative code, not retroactive claims about the original game.

Debugging record

The available archive demonstrates the experience but does not establish a specific production timeout or duplicate-reply incident. A request-to-progression recording is needed. The new example makes late-turn rejection and reset invalidation inspectable without exposing the original implementation.
