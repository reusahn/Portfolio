INDEPENDENT GAMEPLAY PROJECT / TEMPORAL PUZZLE / UNITY C# TARGET

Echo Relay.

A spatial puzzle where a player leaves a moving record of their past self. What they do now becomes an action another version of themselves can perform later. The challenge is to synchronize present decisions with a time-delayed companion—not simply replay a cinematic ghost.

02 / GAME DESIGN

What makes the mechanic worth exploring.

A ghost must change the space, not just mirror a player's animation. A successful puzzle depends on recording useful actions and then performing complementary actions at the right moment.

Time becomes an actor.

Movement from the first pass becomes a replayable actor with a stable schedule. The player reasons about what their past action will activate, not merely where the character will stand.

Present and past have separate responsibility.

The echo owns a timed trigger, while the present player traverses the gate. Both are necessary, creating cooperation without a second connected player.

Failure teaches the timing rule.

If the player reaches a closed gate before the echo activates the plate, they can observe what must change. In the full game, the feedback would include a light/sound response and visible replay trail.

Future puzzle vocabulary.

Light-gated materialization, moving switches, overlapping recordings and limited echo memory. A level only adds another rule when the earlier one is readable and satisfying.

LEVEL 02 / SIGNATURE MECHANIC

Light makes memory physical.

The first puzzle teaches recording and replay. The next level adds a rule that makes the echo genuinely interactive: a remembered body can press switches or hold an object only while the present player illuminates it. The player must plan a past route and then actively support it from a different position.

Past self — a scheduled path

The replay follows its immutable recorded movement, visible as a soft trail. Without directed light from the present player it passes through most interactive objects without activating them.

Present self — materializes the memory

The player points or positions a bounded light cone across the echo. While illuminated, the recorded body becomes tangible to switches and moveable puzzle objects. Moving the light away releases them.

The coordination problem

Record a path through two switches, then relocate to a vantage point that can illuminate the right portions of the path at different times. Position and timing create tension without requiring a second player.

Game-design constraints

Provide explicit light-cone feedback, avoid unsolvable recordings, make the rewind/reset cost low, and ensure the player can infer which actions require illumination. Replaying a path alone should not complete the puzzle.

EchoCollisionWindow.cs

Checks recorded ghost position against the present player's cone using range, facing angle and occlusion. Publishes tangible/not-tangible as a gameplay state rather than merely a material effect.

Deterministic overlap

Reconstructs the echo pose by fixed tick; uses authoritative overlap tests to activate switches only during valid light windows. Visual interpolation does not affect rule evaluation.

Expressive feedback

Footsteps gain weight, the ghost silhouette grows solid and the illuminated path resonates when both times overlap. Presentation follows the gameplay state rather than pretending to be the system itself.

Development distinction: The browser demo demonstrates the first puzzle's record/replay/switch mechanic. Light-gated materialization and the second authored level are target Unity features, not implemented in that browser build.
03 / TARGET UNITY ARCHITECTURE

A deterministic time-offset gameplay system.

The engine implementation separates input sampling, action recording, playback and world-state evaluation. Recording should use fixed simulation ticks so level triggers remain reproducible.

Player input→Tick-indexed movement records→Ghost replay actor→Pressure plate evaluation→Gate / level state
PlayerRecorder.cs

Samples authoritative movement state and discrete interact events into a bounded recording window. A completed take is immutable until re-recorded.

EchoPlayback.cs

Replays the exact tick/time index, reconstructs transforms and issues only permitted echo interactions. Rendering is interpolated independently of gameplay checks.

PuzzleTrigger.cs

Classifies player and echo contacts, evaluates authorable conditions, drives world changes, and resets cleanly after failed attempts.

LevelTestTools.cs

A designer selects memory duration, echo count, trigger intervals and route geometry with visual previews in-scene rather than adjusting custom puzzle scripts.

Playback correctness

Test repeat-run consistency, framerate variance, pausing, stale input and echo reset. Prefer tick-indexed state over floating-time assumptions for physics-critical switches.

Production handoff

Provide a Unity level and short design sheet: puzzle objective, intended player discovery, failure points, exact code responsibilities and an iteration captured after testing.
