2026 / Quantitative benchmark · PyTorch · Nerfstudio

NeuralScene Bench

Question: Under a matched nominal optimization budget, how do 3D Gaussian Splatting and NeRF compare on held-out reconstruction quality?

Method: two Mip-NeRF 360 scenes; common COLMAP data path, image scale and held-out selection; 5,000-step runs; camera refinement disabled for Nerfacto to avoid a default-setting confound.

Result: Splatfacto achieved higher held-out PSNR and SSIM and lower LPIPS on both tested scenes. This is a bounded fixed-step result, not a universal claim about convergence or efficiency.

2026 / Causal diagnostic · 4D human deformation

Human Deformation Locality

Question: when one articulated joint moves, does the learned Gaussian deformation remain anatomically local?

Method: frozen test plan over three pretrained HUGS checkpoints, two preselected joints and 36 nested pose diagnostics. Compared learned effects to a subject-specific K=6 reference and a selective branch-ablation intervention.

Finding: the worst tested K6 reduction was 99.71%; all six joint-by-checkpoint cells met the preregistered diagnostic criteria. The independent model count is three, not 36.

Limitation: diagnostic of existing models, not a new trained correction method or an independent population-wide generalization claim.

2024 / Deployed interaction · Unity · Language model API

Escape Metro: models inside game rules

A protected-information LLM dialogue becomes a game objective inside a Unity VR escape experience. Model behavior affects what the player tries next, while world progression is controlled through explicit application logic.

Research relevance: first-hand awareness that probabilistic model output can be ambiguous, that game-state interpretation requires careful boundaries, and that unexpected behavior can be a meaningful gameplay event.

Scope: an interactive application with an existing model API, not evidence of training a new language model.

02 / Research proposal + executable baseline

What counts as unexpected gameplay?

Designed specifically around game QA, multimodal context, and anomalous behavior detection. A small reproducible browser baseline makes the evaluation problem tangible before any claims of learned intelligence.

Game Signal Anomaly Lab

A playable research workbench generates labeled synthetic traces for normal motion and three failure classes: movement spike, sustained stall, and input–motion disagreement. A transparent rule-based detector scores each trace.

Change the failure class, noise level, and detection threshold. Inspect the event timeline and the confusion matrix. Metrics are recomputed from the generated trace each time—not hard-coded results.

Honest methodological boundary

Implemented here: deterministic synthetic-trace generator, explicitly defined anomaly labels, interpretable residual-style baseline, threshold sweep, and performance counts.

Not implemented: learned image/video embeddings, audio processing, gamepad datasets, model training, real QA bug ground truth, or demonstrated cross-title generalization.

The next phase is not to declare the toy baseline state of the art; it is to define a real research protocol that could disprove it.

RESEARCH QUESTION

Can a model detect gameplay anomalies without confusing novelty with failure?

A speed change may be a bug, a deliberate dash, or a scripted transition. A useful model should represent player intent, scene context and game-state transitions—not just flag rare pixels or high optical flow. My proposed unit of analysis is a time-aligned gameplay segment with video, controller inputs and optional engine telemetry.

MODEL PROGRESSION

From simple baselines to multimodal representations.

Baseline: robust time-series residuals and change-point features on gameplay signals. Video candidate: frozen frame/video encoder for visual states and motion. Input candidate: controller action embeddings and action-to-motion consistency. Fusion candidate: late-fusion score model compared against video-only and input-only ablations. These are planned experiments, not completed training runs.

EVALUATION DESIGN

Events, not just frame accuracy.

Predefine anomaly episodes and detection tolerance. Report per-class event precision/recall/F1, false alarms per hour of normal gameplay, detection latency, calibration, and failure breakdown by title, visual style, and player behavior. Hold out entire gameplay sequences and at least one scenario family to test generalization. Audit leakage from debug overlays or scripted capture artifacts.

FAILURE ANALYSIS

Investigate false alarms before increasing model capacity.

Expected challenging negatives: intentional idle states, menus and pauses, scripted knockback, cutscenes, dash boosts, loading transitions, dropped frames, and unusual-but-valid play. A model that triggers on these would create more QA work rather than reduce it.

03 / Reproducibility and deliverables

What a research review should be able to reproduce.

Concrete artifact roadmap for a genuine ML anomaly detection study. The evaluation is useful only when the data partition, baselines, negative controls, and error cases remain inspectable.

Dataset specification

Consent and rights-safe game captures, time-aligned modality schema, annotation handbook, event ontology, and train/validation/test partitioning that avoids near-duplicate temporal windows.

Executable experiments

Python/PyTorch training and evaluation scripts, pinned environment, fixed seeds, baseline thresholds, ablation matrix, and versioned model/data manifests.

Research report

Per-class quality, false alarms per hour, detection delay, robustness to interface transitions, explicit limitations and representative misclassifications with reproducible examples.

Background / Research positioning
