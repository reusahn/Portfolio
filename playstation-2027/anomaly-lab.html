Game Signal Anomaly Lab

A controlled test of one question: can a detector distinguish game-state mismatch from unusual but valid motion? This workbench uses synthesized controller and movement signals with labeled events. It does not use gameplay video, a pretrained vision-language model, or a published model.

Experiment controls

Model context

An unmodeled boost can look like a bug. Check this to add known game-state context to the expected-motion baseline.

Fixed random seed (2027), 64 timesteps at 2 Hz. No external data, model inference, analytics, or server uploads.

Transparent experimental specification

One baseline; clear failure modes.

This is the first rung on a research ladder, intentionally designed so a reviewer can understand exactly what is—and is not—being measured.

Data-generation protocol

The input trace has smooth periodic variation. Actual velocity follows a scaled version of that input plus seeded noise, except during an intentional speed boost (frames 9–14) and optional labeled bug episode (frames 30–36). No hidden test-set selection, trained parameters, or proprietary game data are involved.

Bug classes: stall forces low velocity; spike adds unexpected positive velocity; reverse flips the expected direction. A fourth negative-control condition injects no bug.

The intended boost is not a bug. Treating it as one exposes a classic confound: unusual action need not mean erroneous action.

Detector and measures

Predicted motion is 1.75 × control input, plus a known boost term only when the context option is enabled. The anomaly score is the absolute difference between predicted and measured velocity. A frame raises an alarm when score exceeds the selected threshold.

Ground truth is a per-frame boolean label for the injected bug segment. Counts: true positives, false positives, false negatives and true negatives. Precision = TP/(TP+FP); recall = TP/(TP+FN). When no positives exist, the corresponding measure is reported as undefined.

This design tests interpretation and threshold behavior, not deep learning quality.

FAILURE CASE

Intentional speed boosts create false positives without context.

Try the no-bug scenario with context disabled. Lower the threshold to observe how a real but legal game mechanic can be misclassified. Turn on game-state context and compare alarm counts. This is why a future model should consume game actions or state transitions alongside visual features.

REPRODUCIBILITY

Export the current trace.

The CSV includes timestep, input signal, measured motion, baseline expectation, boost flag, ground-truth bug label, residual anomaly score, and detector decision. Settings are embedded as header comments. This permits a quick external check of the displayed counts.

Limitation: synthetic labels are known because the code generates them. Any numerical result on this page is a baseline sanity check, not evidence of generalization to gameplay bugs, accessibility outcomes, or the GameLens platform.
