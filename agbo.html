HOW I WORK

Technical art starts before the asset reaches the engine.

I prefer to define the complete path early, then expose only the controls artists and directors need while keeping downstream constraints visible.

01Creative Goal

Understand the image, performance, interaction, or narrative intent before choosing the technical solution.

02Constraints

Identify source quality, rig / topology rules, runtime limits, platform needs, and downstream dependencies.

03Prototype

Build the shortest working path in engine or DCC and test the risky technical assumption first.

04Expose Controls

Turn shader, animation, lighting, or system parameters into useful art-direction controls.

05Stress Test

Check different assets, performances, cameras, lighting states, devices, or source-data failures.

06Document / Scale

Define repeatable requirements, fallback paths, and handoff rules so the next asset is cheaper than the first.
