WORKING TITLE · UNITY C# · TWO-PLAYER ONLINE CO-OP

Windward.

Two players, two complementary forces, one shared goal. An online co-op prototype in which one player lifts a drifting seed while the other steers it through a sequence of floating environments.

PROPOSED GAMEPLAY PROTOTYPE — DEVELOPMENT BRIEF
GAMEPLAY RELATIONSHIP DIAGRAM · NOT A GAMEPLAY SCREENSHOT
01 / PLAYER EXPERIENCE

A small mechanic with genuine interdependence.

The game is designed around cooperation rather than two players doing the same thing. Neither can complete a level alone: vertical lift and horizontal steering must be combined to move a fragile seed past obstacles into a safe landing zone.

PLAYER A

Lift the seed

Generate updrafts to control height, slow a fall, and navigate changing elevation.

PLAYER B

Shape its direction

Apply horizontal wind to steer, correct momentum, and guide the seed around obstacles.

SHARED GOAL

Reach the next shelter

Coordinate timing and force across an obstacle course. A failed attempt resets the current checkpoint.

02 / DESIGN × ENGINEERING

Proposed technical architecture.

A compact vertical slice that demonstrates gameplay systems, multiplayer synchronization, authored tools, readable feedback, and repeatable playtest delivery.

Shared simulation

Unity C# physics state for seed position, velocity, airflow and collisions. A host-authoritative simulation distributes a canonical world state to both clients.

Networked co-op

Planned Unity Netcode for GameObjects integration with multiplayer input ownership, interpolation, disconnect behavior and a two-client verification run.

Player feedback

Wind force affects shader motion, cloud density, particles, audio and camera response so an invisible force has a readable consequence.

Designer-facing controls

Inspector-driven presets for camera damping, wind strength, obstacle spacing, checkpoint rules and difficulty, allowing new level layouts without code changes.

Testing & operation

Versioned multiplayer builds, structured issue logging, reproducible playtests and a patch/change log to track post-test improvements.

Performance boundaries

Separate physics and network state from shader rendering so visual fidelity can be tuned independently of synchronized interaction.

03 / IMPLEMENTATION PLAN

Evidence the prototype is intended to produce.

  1. Playable local loop — seed motion, complementary wind controls, obstacle collision, checkpoints and failure/retry states.
  2. Two-client multiplayer test — remote players sharing the same seed and level, with synchronized input effects and visible latency behavior.
  3. Game-feel iteration — side-by-side tuning of camera, force response, shader readability, audio and failure feedback.
  4. Designer tooling — configurable wind/camera presets, level parameters and reproducible content setup.
  5. Playtest and build history — playable release candidate, test results, fixes, version notes and a documented update.
