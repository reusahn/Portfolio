MULTI-USER SYSTEMS / UNITY C# / REAL-TIME DEPLOYMENT

Jemulpo Photo Studio.

A live, visitor-facing portrait system designed for up to four simultaneous participants. Unity and computer-vision processing transform each visitor into a stylized period portrait, then distribute the result to a continuously updated display wall.

ROLETechnical Director / Unity Developer YEAR2022 VENUEIncheon Metropolitan Museum SYSTEMUnity C# · Python · OpenCV · Barracuda · TCP/UDP

Existing exhibition footage · Multi-participant interactive portrait pipeline

01 / DESIGN INTENT

Many visitors. One continuously changing installation.

Visitors actively generate the work. Each session captures and transforms a portrait, while a separate wall display accumulates the resulting images. The interaction, vision pipeline, storage and external presentation must operate together without manual file transfer.

Interaction and content

Visitors stand at an interactive portrait station. The system identifies and separates a person, applies the visual treatment, saves an image and adds the result to the gallery.

Technical ownership

Technical direction and Unity C# system integration, connecting the visitor-facing application with OpenCV/Barracuda image processing, output management, network delivery and exhibition playback.

02 / SYSTEM DESIGN

The real-time pipeline.

Network communication was part of a larger content system. A completed portrait moves between processes and screens; the gallery continues to update as visitors participate.

Visitor capture→Face detection / OpenCV→Person segmentation / Barracuda→Stylized portrait→Local archive→TCP delivery→Gallery display

Capture + segmentation

OpenCV face/head-region detection and Barracuda person segmentation prepare the image for stylized composition with period-inspired graphic treatments.

Cross-device output

Processed portraits are saved automatically into timestamped folders and sent via TCP to an external display system, creating an accumulating gallery display without manual intervention.

Multi-participant format

The application was developed for a deployment with up to four simultaneous participants, according to the project resume. This is multi-user exhibition software—not synchronized online game simulation.

Operational continuity

Production adjustments included resolving audio buffering and playback interruptions so the exhibition experience could continue between visitor sessions.

03 / DESIGN–ENGINEERING DECISIONS

Make a complex system usable by visitors.

Each technical boundary carries an interaction requirement: the person must see feedback, the generated content must persist and the public display must receive it.

Keep the visitor loop immediate.

Capture, segmentation and visual transformation are presented as one experience rather than a disconnected offline image-processing task.

Separate capture from presentation.

Portrait creation and wall display are different responsibilities. Transmitting completed images allows the exhibition wall to update independently.

Make output reproducible.

Timestamped folders and automatic archival make the finished images available for continued display and exhibition management.

05 / RELEVANCE TO GAME DEVELOPMENT

Shipped interactive software across machines.

The transferable experience is in making a real-time application coordinate inputs, media processing, networked outputs and public-facing operation. It is materially relevant to gameplay tools and multiplayer workflows, while remaining distinct from shipping a commercial online game.

What this demonstrates

What it does not imply
