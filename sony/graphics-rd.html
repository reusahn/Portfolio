01 / procedural cloud

Expose shader behavior through runtime controls.

Perlin-driven vertex displacement produced internal cloud motion in Unity URP. C# interpreted directional input and passed values into the material so the noise flow could follow player input and art direction.

The two views below show the runtime result and the Unity development setup for the same technical system.

Production decision

Keep runtime interaction controls connected to the visual parameters the artist needs.

02 / metaball system

Keep controllable droplets and the rendered liquid field distinct.

Droplets remained separate GameObjects with C# movement, contact / proximity recognition, grouping, and positional correction. A leader / follower relationship maintained the collected group.

A custom HLSL raymarched metaball field made the separate objects read as a continuous liquid mass.

Production decision

Choose an interaction representation and a rendering representation for their separate responsibilities.

LayerResponsibility
C# / GameObjectsMovement, collision, group membership, leader / follower behavior, and positional constraints.
HLSL / implicit fieldThe continuous metaball appearance and visual blending between nearby droplets.
03 / fixed topology growth

Author a transformation that preserves vertex correspondence.

I created exactly four matching-topology cloud-growth states in Maya, retaining vertex count and ordering across the targets.

Unity Timeline / Animation drove the blendshape weights, making the growth predictable, repeatable, and directly editable.

Production decision

Preserve stable topology when reliable blendshape interpolation is the delivery requirement.
