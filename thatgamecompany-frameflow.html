02 / INTENDED UNITY FEATURE

A reusable camera feature, not a one-off level script.

In a production Unity version, the camera behavior would be split into a runtime controller and designer-authored data. Each encounter could request a camera profile; designers could preview changes within a level and commit them as reusable assets.

Runtime camera controller

Position smoothing, velocity-based look-ahead, bounded focus, zoom, transitions, and obstruction checks. Parameter-driven C# behavior separate from the visual scene.

Designer-authored profiles

ScriptableObject camera presets expose damping, offset, zoom and zone boundaries, with consistent application across content and test scenes.

Editor toolset

A custom inspector and scene gizmos would allow designers to visualize target frames and edit zone volumes in level context without code changes.

Validation and handoff

Capture baseline/modified camera clips, evaluate obstacle visibility, frame timing and transitions, and document reproducible adjustments for the rest of the design team.
