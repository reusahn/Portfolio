Case Overview

What I owned and why the work mattered.

This project is intentionally placed after the Unreal cases. Its value for Snail Games is graphics depth, not engine identity. C# kept gameplay objects, movement, collision, grouping, and state explicit while HLSL produced the continuous liquid appearance through procedural deformation and a raymarched metaball field.

01

Shader Authoring

Custom HLSL for Perlin vertex deformation, Fresnel response, and raymarched field rendering.

02

Runtime Architecture

C# controls input, collision, grouping, leader / follower rules, and shader parameters.

03

Deterministic Geometry

Fixed-topology Maya states preserve vertex correspondence for predictable transformation.

04

Production Debugging

Rendering and gameplay logic remain separable, testable, and reusable during iteration.

Technical Breakdown

From source problem to validated production result.

02Separate Systems

Create matching-topology Maya targets for predictable visual growth.

05Validate

Test rendering behavior and gameplay response together in context.

Takeaway

The transferable skill is the technical-art reasoning: isolate the actual production problem, build a controllable system, preserve art direction, and keep the runtime implementation debuggable.
