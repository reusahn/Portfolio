02 / GAME DESIGN PROBLEM
Cooperation must be authored, not hard-coded.


A prototype can have a single scripted door. A production tool must let a designer create new encounters—by composing player conditions, rule timing, world actions and response presets—without requesting a new C# class for each level.




Encounter A — Shared Gate
The lift and horizontal force must satisfy a combined condition for a sustained interval. The gate opens, a soft wind motif plays, and the camera widens for the reveal. Each player's input alone is insufficient.


Encounter B — Wind Bridge
Both inputs shape a temporary passage. High lift stabilizes the seed while a controlled lateral current extends a traversable bridge. The bridge collapses if the cooperative force is not maintained.


Encounter C — Quiet Guardian
An AI creature responds to restraint, not maximum force. Low disturbance encourages approach; abrupt force makes it withdraw. Gaze, head pose and stepping are procedural reaction channels.


Reusability
One authoring format produces three different encounters. A designer edits thresholds, timing, action targets and feedback independently, rather than duplicating custom encounter scripts.






03 / PROPOSED UNITY SYSTEM
Runtime contract and level-editor workflow.


Designed to work alongside Unity's existing systems rather than replace them. Cinemachine continues to own camera follow and framing. Animator / Animation Rigging own character playback and procedural pose adjustments. The toolkit owns game-specific cooperative conditions, event ordering and designer-facing authoring.


Owned player inputs→Host-validated game state→Encounter evaluator→Encounter action→Feedback adapters




EncounterDefinition : ScriptableObject
Serializes conditions, thresholds, hold times, target IDs, action ordering and feedback preset references as reusable data assets.


EncounterEvaluator : C# runtime
Consumes canonical game-state snapshots, maintains condition timers, dispatches one-shot state transitions and supports reset/checkpoint semantics.


EncounterEditor : EditorWindow
Lists authored encounters, previews triggers in a sandbox scene, shows rule evaluation over time, exposes handles for volumes and validates missing references.


Game-feel adapters
Pure gameplay state events drive Cinemachine profiles, HLSL material parameters, VFX Graph or Niagara-equivalent Unity effects, audio cues and Animator triggers.


Procedural creature adapter
Maps proximity, movement intensity and cooperation to approach/flee states, head/eye targets and foot placement through animation layers and Unity Animation Rigging.


Multiplayer state inspection
Read-only visualization compares two players' inputs with host-authoritative encounter outcomes, including latency/disconnect traces. This remains a planned test tool.








04 / DESIGNER ACCEPTANCE TEST
How the tool earns its place in production.
The evaluation is not “does a custom inspector exist?” It is whether another designer can build and revise a meaningful encounter independently and whether the outcome remains deterministic for both players.




Make an encounter
Using only the editor, author a new gate with different thresholds and feedback. No changes to core C# code.


Change the feel
Retune charge duration, camera anticipation and audio/VFX intensity in a test scene. Show the same input replay before and after.


Network consistency
Two connected clients receive the same authoritative encounter result; a delayed input cannot independently trigger an unauthorized world state.


Debuggable states
Display each rule's operands, timer, activation edge and reset cause. Reproduce a failure from captured input and session events.


Designer handoff
Write a one-page quick-start guide, ask another person to create a variant encounter, observe blockers and make one improvement based on feedback.
