Independent Real-Time Game R&D

A technical-art case focused on custom shader authoring, runtime behavior, procedural deformation, raymarched forms, and deterministic character transformation systems in Unity URP.

Technical Artist / Technical DirectorUnity URPC#HLSLPerlin Vertex DeformationFresnelRaymarchingMaya Blendshapes

System architecture

Rendering layer

Custom HLSL handled the continuous visual behavior: procedural vertex deformation, Fresnel response, and raymarched metaball-style fields.

Runtime layer

C# kept gameplay-side input, object state, grouping, movement, and visual parameters explicit so rendering logic did not become entangled with interaction logic.

Geometry layer

Multiple Maya transformation states used fixed topology so vertex correspondence stayed predictable across the character's visual growth states.

Iteration layer

Gameplay behavior and graphics behavior could be tested separately, then evaluated together in the Unity runtime.

How the system was built

01 · Define the visual behavior

Broke the art direction into technical components: continuous surface motion, liquid-like fusion, silhouette change, and controllable runtime transformation.

02 · Prototype deformation

Built Perlin-driven vertex deformation in HLSL and exposed parameters that could be tuned from Unity instead of hard-coding one visual result.

03 · Surface response

Added Fresnel-based response to reinforce edge readability and help the procedurally moving form remain legible under real-time lighting.

04 · Raymarched field prototype

Developed raymarched metaball-style implicit forms for visual fusion that would be difficult to author as conventional static geometry.

05 · Separate gameplay and rendering

Kept GameObject behavior, input, collision / grouping logic, and state management in C#, while shaders remained responsible for visual synthesis.

06 · Author fixed-topology states

Created multiple Maya target states on matching topology, preserving vertex order so controlled shape transformation remained deterministic.

07 · Blendshape validation

Checked target correspondence and deformation quality before integration, avoiding late runtime errors caused by mismatched geometry states.

08 · Runtime state integration

Connected the transformation states to Unity animation / Timeline and runtime parameters so the visual system could respond to controlled game-side state changes.

09 · Combined testing

Evaluated graphics and gameplay behavior together, checking whether the shader effect still communicated clearly during movement and interaction.

10 · Production debugging

Kept each layer separable enough to isolate whether a failure came from source geometry, animation state, C# logic, or HLSL rendering.

Only publicly shareable material is described here. The focus is the technical method: building a controllable bridge between art direction, geometry, gameplay state, and real-time graphics.
