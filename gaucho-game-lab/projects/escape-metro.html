Escape Metro

A surreal Unity VR escape game combining spatial puzzle solving, a real-time conversational NPC, CC4 character integration, runtime state logic, and standalone Meta Quest 3 deployment.

Director / Technical ArtistUnity URPMeta Quest 3ChatGPT APICC4Runtime DialogueXR InteractionStandalone Optimization

Experience architecture

Spatial escape-game loop

The player explores a VR environment, reads spatial cues, solves progression problems, and interacts with the scene instead of navigating a flat dialogue interface.

Conversational NPC

A ChatGPT-driven dialogue layer is embedded into the game flow so conversation can participate in progression rather than existing as a detached chatbot demonstration.

Digital-human implementation

CC4 character assets, animation, and blendshape-based facial behavior were integrated into Unity so the AI interaction had an embodied in-world presence.

Standalone VR delivery

The project was built for Meta Quest 3, requiring game logic, character rendering, XR interaction, and dialogue systems to coexist within standalone-device constraints.

How I built the project

01 · Prototype the escape loop

Established the core room-scale experience first: spatial navigation, puzzle progression, doors, and scene-state changes needed to work before adding the AI layer.

02 · Build XR interaction

Connected the player's VR interaction to world objects and progression logic so actions inside the scene could change the current game state.

03 · Prepare CC4 characters

Imported Character Creator assets into Unity, validated rig / animation behavior, and prepared blendshape-based facial presentation for runtime use.

04 · Add character animation

Connected the character's animation behavior to the experience so the NPC read as part of the world rather than as a static conversational interface.

05 · Build the dialogue request flow

Connected player conversation to the ChatGPT API and returned generated responses into the Unity runtime instead of treating AI output as an external tool.

06 · Connect dialogue to game state

Linked conversational logic with the escape-game progression so dialogue could influence what the player understands or can do next.

07 · Add voice interaction

Combined voice input and generated NPC responses to make the interaction immediate inside VR and reduce dependence on conventional keyboard-style UI.

08 · Present responses through the character

Connected the response layer to the in-world NPC presentation, coordinating dialogue, facial behavior, and character timing as one interaction loop.

09 · Integrate puzzle / door logic

Kept puzzle state, door behavior, navigation, and conversation connected through the same runtime structure so AI interaction remained part of gameplay.

10 · Optimize for Quest 3

Adjusted shaders, lighting, assets, character presentation, and runtime decisions for standalone hardware, then repeated testing directly on the target device.

11 · Device-side validation

Checked the complete system on Quest rather than relying only on the Unity Editor, where XR input, rendering cost, and runtime behavior can differ from the final headset build.

12 · Public deployment

Prepared the experience for a public showcase at the Seongsu KAIA pop-up store, where the application needed repeatable operation for users outside the development environment.

The main technical point is integration. AI, character animation, XR interaction, puzzle state, and device performance were built as one runtime experience rather than five disconnected demos.

Standalone-VR constraints

Quest 3 forced practical trade-offs across shader complexity, lighting, character cost, runtime systems, and visual fidelity. The final decisions were validated through repeated device builds rather than assumed from desktop performance.

Why it matters for a game lab

Escape Metro combines game-state design, digital-human implementation, conversational AI, Unity engineering, XR interaction, and deployment. It demonstrates that I can connect experimental technology to an actual playable loop.
