Escape Metro.

A Unity VR escape game where dialogue is the puzzle mechanic. Players interrogate an AI NPC to discover a password and progress toward escape—connecting conversational input to concrete objectives rather than using AI as ambient dialogue.

01 / PROBLEM & OWNERSHIP

A design problem translated into a runtime system.

The distinction between creative objective and technical contribution is central to this case.

Design / production challenge

Players should have a reason to talk to the NPC beyond hearing scripted exposition. The game’s LLM-jailbreaking idea turns conversation into a practical problem: uncover information that reveals a password and enables escape, while staying inside a navigable headset world.

My technical contribution

I designed and developed the Unity VR escape experience, including the player interaction path, AI NPC integration, speech-response presentation, character animation, and Quest-oriented environment. The prior application resume identifies password discovery through AI dialogue as a core gameplay mechanic.

GAMEPLAY DESIGN / OBJECTIVES

Conversation becomes a puzzle.

In the gameplay loop, the player needs information from an AI NPC to make progress. Conversational problem solving is tied to a password and escape conditions, giving dialogue a concrete game-design purpose.

Explore subway→Encounter AI NPC→Ask / probe→Discover password clue→Progress toward escape
What is the player's objective?

Discover a way to escape rather than simply listen to character dialogue. Password and progression provide a clear, external goal.

Why an AI NPC?

The player can experiment with how questions are framed. The LLM-jailbreaking concept becomes a playful information-discovery mechanic.

How is feedback delivered?

The NPC responds inside the VR scene using speech and character performance, keeping puzzle solving embodied in the environment.

02 / IMPLEMENTATION

How the feature works.

Concrete subsystems and boundaries, not only a list of software tools.

Spatial gameplay

The subway level provides navigable space, clues and escape objectives. Conversational discovery influences the player's progress through the puzzle.

Voice-to-character loop

Player speech enters a speech-recognition and AI response pipeline and is returned through an in-world character.

Readable NPC state

Facial blendshapes, lip sync and Animator state connect character delivery to the conversation.

Headset delivery

Unity URP, XR Interaction Toolkit and Quest constraints shaped runtime and lighting choices.

Player voice / input→Unity XR + speech input→AI response→NPC animation / audio→Player interpretation
03 / TECHNICAL DESIGN

Decisions that make iteration possible.

Each technical decision supports clarity, performance, or cross-disciplinary change.

Keep dialogue spatial

The conversational character lives inside the level, so interaction remains attached to world exploration.

Separate character and dialogue

The NPC visual rig and animation can be validated independently of the conversational service.

Build for the device

Lighting, audio and shader complexity are considered for a standalone Quest runtime.
